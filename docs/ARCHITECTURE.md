## 1. 架构概述

SmartWin AI Governance Platform 采用云原生微服务架构，由三大核心平台组成：

```
┌─────────────────────────────────────────────────────┐
│                  SmartWin Platform                   │
│                                                     │
│  ┌──────────────┐  ┌──────────────┐                │
│  │  SmartData   │  │  SmartChain  │                │
│  │  数据治理平台 │  │  AI协同链    │                │
│  └──────┬───────┘  └──────┬───────┘                │
│         └────────┬─────────┘                        │
│              ┌───▼────────┐                         │
│              │ SmartWin   │                         │
│              │ 集成层     │                         │
│              └────────────┘                         │
└─────────────────────────────────────────────────────┘
```

### 1.1 设计原则
- **微服务**: 服务独立部署，松耦合
- **云原生**: 容器化，Kubernetes编排
- **API优先**: 所有功能通过API暴露
- **事件驱动**: 异步消息解耦服务
- **可观测性**: 日志、指标、追踪全覆盖
- **安全优先**: 零信任安全模型

| smartwin-gateway | 8080 | API网关，路由、认证、限流 |

| smartchain-llm | 8092 | LLM集成服务 |
| smartchain-workflow | 8093 | 工作流引擎 |
| smartwin-auth | 8100 | 认证授权服务 |
| smartwin-monitor | 8110 | 监控告警服务 |

### 3.2 服务间通信

```
同步通信 (HTTP/REST):
  客户端 → Gateway → 业务服务

异步通信 (Message Queue):
  服务A → RabbitMQ/Kafka → 服务B

服务发现:
  所有服务 → Nacos → 实例列表
```


## 5. 安全架构

### 5.1 身份认证
- 使用 Keycloak 作为身份提供者 (IdP)
- OAuth 2.0 + OIDC 标准协议
- JWT Token 无状态认证
- 多因素认证 (MFA) 支持

### 5.2 授权控制
- RBAC (基于角色的访问控制)
- 细粒度资源权限
- API网关统一鉴权
- 数据行级别权限

### 5.3 数据安全
- 传输加密: HTTPS/TLS 1.3
- 存储加密: AES-256
- 敏感数据脱敏
- 数据访问审计日志

## 6. 部署架构

### 6.1 环境规划

| 环境 | K8s集群 | 用途 |
|------|---------|------|
| 开发 | 本地 Docker Compose | 本地开发 |
| 测试 | K8s (2节点) | 集成测试 |
| 预发布 | K8s (3节点) | UAT验收 |
| 生产 | K8s (5节点+) | 生产运行 |

### 6.2 高可用设计
- 所有服务至少2个副本
- 跨可用区部署
- 数据库主从复制
- Redis哨兵/集群模式
- 负载均衡 + 健康检查
