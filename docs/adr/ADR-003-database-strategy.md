# ADR-003: 数据库战略

## 状态
已接受 (Accepted)

## 日期
2026-01-25

## 背景与问题陈述

SmartWin 平台需要存储多种类型的数据：
- 结构化业务数据（资产、用户、权限）
- 图关系数据（数据血缘、知识图谱）
- 全文检索数据（日志、文档）
- 时序数据（监控指标）
- 向量数据（AI嵌入）
- 文件/二进制数据

## 多模型数据库策略 (Polyglot Persistence)

根据数据特性选择最适合的存储方案：

| 数据类型 | 选择方案 | 理由 |
|---------|---------|------|
| 业务实体数据 | MySQL 8.0 | ACID事务，成熟可靠 |
| 缓存/会话 | Redis 7.2 | 极高性能，丰富数据结构 |
| 日志/全文搜索 | Elasticsearch 8.10 | 水平扩展，聚合分析 |
| 知识图谱/血缘 | Neo4j 5.x | 图遍历性能卓越 |
| AI向量嵌入 | Milvus 2.3 | 专用向量数据库 |
| 文件对象 | MinIO | S3兼容，本地可部署 |
| 监控时序数据 | Prometheus | 专为监控设计 |

## MySQL设计决策

### 分库策略
- 按业务域分库，不同微服务使用独立数据库
- 初期不做分表，单表超过5000万行时评估

### 字符集
- 统一使用 `utf8mb4` + `utf8mb4_unicode_ci`
- 支持完整Unicode，包括emoji

### 连接池
- 使用 HikariCP (Spring Boot默认)
- 最大连接数配置: 根据实例规格，通常 20-50

### 软删除
- 所有业务表使用 `is_deleted` 字段实现软删除
- 查询时统一过滤 `is_deleted = 0`

## 缓存策略

### 缓存层次
```
L1: JVM本地缓存 (Caffeine) - 热点数据，毫秒级
L2: Redis集群缓存 - 共享缓存，毫秒级
L3: 数据库 - 持久化存储，毫秒-秒级
```

### 缓存失效策略
- TTL过期: 适合不频繁变化的数据
- 主动更新: 数据变更时主动刷新
- 写穿透: 写入时同时更新数据库和缓存

## 数据迁移策略

### 工具选择: Flyway
- 所有DDL变更通过Flyway版本化管理
- 文件命名: `V{版本}_{描述}.sql`
- 示例: `V1__create_data_asset_table.sql`

### 迁移原则
- 每次迁移文件不可修改（immutable）
- 向后兼容的变更（加列、加表）
- 破坏性变更分多步进行

## 结果与影响

**正面影响:**
- 每种数据使用最适合的存储，性能最优
- 各存储独立扩展

**负面影响:**
- 运维复杂度增加（多种数据库）
- 需要维护多种技术的专业知识

**缓解:**
- 使用Docker统一管理所有数据库
- 详细的运维文档
- 监控告警覆盖所有数据库
