# ADR-001: 技术栈选择

## 状态
已接受 (Accepted)

## 日期
2026-01-15

## 背景与问题陈述

SmartWin AI Governance Platform 需要选择一套合适的技术栈，以支持：
- 高性能、高并发的企业级数据治理功能
- 复杂的AI/ML工作流编排
- 可扩展的微服务架构
- 丰富的前端交互体验

## 决策驱动因素

1. **团队技术能力**: 团队成员以Java/Spring背景为主
2. **企业级成熟度**: 需要经过大规模生产验证的技术
3. **AI集成能力**: 需要强大的LLM集成支持
4. **生态系统**: 丰富的开源工具和社区支持
5. **可维护性**: 良好的代码可维护性和可测试性

## 考察的选项

### 选项A: Java (Spring Boot) + Vue 3 + Python (FastAPI) [推荐]
**优点:**
- 团队技术栈契合度高
- Spring Cloud生态成熟，微服务支持完善
- Vue 3 + TypeScript前端开发体验优秀
- Python生态在AI/ML领域无可替代

**缺点:**
- 多语言技术栈增加维护成本
- Java应用启动速度相对较慢

### 选项B: Node.js (NestJS) + Vue 3 + Python
**优点:**
- 前后端统一JavaScript语言
- NestJS架构清晰

**缺点:**
- Java后端生态（JPA、Spring Security等）更成熟
- 团队缺乏NodeJS后端经验

### 选项C: Go + Vue 3 + Python
**优点:**
- Go性能优秀，资源占用少

**缺点:**
- 团队Go技术储备不足
- 学习成本高，项目风险大

## 决策结果

**选择选项A**: Java (Spring Boot 3.x) + Vue 3 (TypeScript) + Python (FastAPI)

## 详细技术选型

### 后端核心
| 技术 | 版本 | 选择理由 |
|------|------|---------|
| Java | 17 LTS | 长期支持，虚拟线程支持，性能优化 |
| Spring Boot | 3.2+ | 成熟框架，开发效率高 |
| Spring Cloud | 2023.x | 微服务全家桶 |
| Nacos | 2.3+ | 国内广泛使用，中文文档完善 |

### 数据层
| 技术 | 版本 | 选择理由 |
|------|------|---------|
| MySQL | 8.0 | 主流关系数据库，社区活跃 |
| Redis | 7.2 | 高性能缓存，数据结构丰富 |
| Elasticsearch | 8.10 | 全文搜索和日志分析行业标准 |
| Neo4j | 5.x | 图数据库领域领导者，适合知识图谱 |

### AI层
| 技术 | 版本 | 选择理由 |
|------|------|---------|
| Python | 3.11+ | AI/ML事实标准 |
| FastAPI | 0.104+ | 高性能异步API，自动文档 |
| LangChain | 0.1+ | LLM应用开发最流行框架 |

## 结果与影响

**正面影响:**
- 团队上手快，降低学习成本
- 技术生态成熟，减少技术风险
- 社区支持充足，问题易于解决

**负面影响/风险:**
- 多语言技术栈增加DevOps复杂度
- 需要为Python服务维护独立的依赖管理

**缓解措施:**
- 统一容器化部署，降低多语言管理复杂度
- 建立清晰的服务边界，Python仅用于AI模块
