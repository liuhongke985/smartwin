# DB 兼容性与备份恢复验收测试用例

目标：验证在达梦 DM8 环境下的兼容性、备份与恢复流程满足生产 RTO/RPO 要求。

## 前置条件
- 准备测试环境（与生产等价网络/IO 约束）
- 已安装 DM8，并准备好备份工具（逻辑备份 & 物理备份）
- 准备示例数据集（含大表、索引、分区表）

## 测试用例列表

1. TC-DB-01: 基础兼容性检查
- 步骤:
  1. 在 DM8 上创建示例 schema 与表结构（DDL）
  2. 执行常用 CRUD 操作（小批量/大批量）
  3. 验证 SQL 兼容性（JOIN、窗口函数、事务隔离级别）
- 期望结果: 所有语句正确执行，结果与 MySQL 对照样例一致

2. TC-DB-02: 性能基线（读写）
- 步骤:
  1. 使用 sysbench 或自定义脚本进行写入压力测试（e.g. 大事务、并发写）
  2. 读取压力测试（100 并发查询）
- 期望结果: 吞吐与延迟在可接受范围内，记录关键指标（TPS、95p 延迟）

3. TC-DB-03: 逻辑备份与恢复
- 步骤:
  1. 使用导出工具（dm8 导出或兼容工具）导出 schema + 数据
  2. 在干净实例上执行导入
  3. 验证数据完整性及索引/约束
- 期望结果: 导入后数据一致且无丢失，导入时间在预期内

4. TC-DB-04: 物理备份与灾难恢复（RTO/RPO 验证）
- 步骤:
  1. 执行物理快照备份（cold/online）
  2. 模拟节点故障，基于备份恢复到新实例
  3. 验证服务可用性恢复时间（RTO）与数据回退点（RPO）
- 期望结果: 恢复在定义 RTO 内完成（建议 ≤ 30min），RPO 满足业务需求

5. TC-DB-05: 大表迁移与分区恢复
- 步骤:
  1. 导入或生成大表（>100G）并创建分区
  2. 测试备份/恢复单个分区的数据恢复
- 期望结果: 分区恢复成功且性能可接受

6. TC-DB-06: 权限与角色迁移
- 步骤:
  1. 导出用户/角色/权限策略
  2. 导入到恢复实例并验证权限控制
- 期望结果: 权限一致性、审计记录存在

7. TC-DB-07: 兼容性回退策略
- 步骤:
  1. 测试在需要回退时从 DM8 切换到 openGauss/MySQL 的兼容性脚本
  2. 验证核心查询/接口正常
- 期望结果: 至少提供可行的回退流程与必要脚本

## 验收标准
- 所有 P0 用例通过
- 关键性能指标记录并满足业务阈值
- 提供完整的恢复Runbook与自动化脚本
