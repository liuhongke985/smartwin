## 1. 总体实施策略

### 1.1 实施原则

| 原则 | 说明 |
|------|------|
| 敏捷迭代 | 2周一个Sprint，快速交付、持续反馈 |
| MVP优先 | P0功能先行，P1/P2后续迭代增强 |
| 纵向切片 | 每个Sprint交付端到端可演示的功能 |
| 持续集成 | 每日构建、自动化测试、持续部署 |
| 文档同步 | 代码与文档同步更新，避免技术债务 |

### 4.3 前端开发规范

| 规范 | 说明 |
|------|------|
| 组件命名 | PascalCase，如 `AssetCard.vue` |
| 文件结构 | views/按功能域分组，components/按类型分组 |
| 状态管理 | 全局状态用Pinia，局部状态用ref/reactive |
| API调用 | 统一通过api/目录封装，使用TypeScript接口 |
| 样式 | 使用CSS变量(Design Tokens)，支持主题切换 |
| 响应式 | 移动端适配(min-width: 768px) |
| 性能 | 路由懒加载、组件按需引入、虚拟滚动 |
