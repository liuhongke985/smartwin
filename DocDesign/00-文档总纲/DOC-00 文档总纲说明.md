## 1. 文档体系概述

### 1.1 文档体系目的

本文档体系总纲为「智赢(智数+智链)双平台」项目建立统一的文档管理框架，确保项目全生命周期内所有文档的规范性、完整性、可追溯性和可维护性。文档体系覆盖从项目启动、需求分析、系统设计、开发实施、测试验收到部署上线、运维运营的全过程。

### 1.2 适用范围

本文档体系适用于：
- 智数AI原生数据治理平台（SmartData）—— AI原生数据治理产品线
- 智链AI模型治理与监控平台（SmartChain）—— AI模型治理与监控产品线
- 智赢集成平台（SmartWin）—— 智数+智链集成产品
- 共享技术底座（Platform Common）—— 两套产品共用的公共模块与服务

### 1.3 文档体系原则

| 原则 | 说明 |
|------|------|
| **规范性** | 所有文档遵循统一的编号规则、模板格式和元数据规范 |
| **完整性** | 覆盖项目全生命周期的每个阶段，不留文档空白 |
| **可追溯性** | 每份文档可追溯到上游需求和下游实现，支持正向/反向追踪 |
| **版本控制** | 所有文档纳入版本管理，变更可追溯 |
| **时效性** | 文档随项目进展同步更新，确保与实际状态一致 |
| **协同性** | 文档支持多人协作编辑，明确各文档的负责人和审批人 |

## 3. 文档生命周期管理

### 3.1 文档状态流转

```
草稿(Draft) → 评审中(Review) → 修订(Revised) → 正式发布(Released) → 变更(Changed) → 归档(Archived)
```

| 状态 | 说明 | 操作人 |
|------|------|--------|
| 草稿 | 初稿编写中 | 文档负责人 |
| 评审中 | 提交评审，收集意见 | 评审组 |
| 修订 | 根据评审意见修改 | 文档负责人 |
| 正式发布 | 审批通过，基线锁定 | 审批人 |
| 变更 | 已发布文档的修改 | 变更申请人 |
| 归档 | 项目结束或文档废止 | PMO |

### 3.2 文档版本规则

采用语义化版本号：`V[主版本].[次版本].[修订号]`

| 版本类型 | 规则 | 示例 |
|----------|------|------|
| 主版本 | 重大变更或里程碑版本 | V1.0 → V2.0 |
| 次版本 | 新增章节或较大修改 | V1.0 → V1.1 |
| 修订号 | 修正错误或小幅调整 | V1.0.0 → V1.0.1 |

### 3.3 文档变更控制流程

```
1. 提出变更申请 → 填写《变更请求日志》(PM-07)
2. 影响分析     → PMO评估变更影响范围
3. 审批决策     → 项目经理/总监审批
4. 实施变更     → 文档负责人修改文档
5. 评审确认     → 评审组确认变更质量
6. 发布基线     → 更新文档版本号和修订记录
7. 通知干系人   → 通知所有受影响方
```

## 4. 文档评审机制

### 4.1 评审类型

| 评审类型 | 触发时机 | 参与人 | 产出 |
|----------|----------|--------|------|
| 需求评审 | BRD/SRS完成后 | 产品+开发+测试 | 评审意见+签字 |
| 设计评审 | 架构/详细设计完成后 | 架构师+开发+测试 | 评审意见+签字 |
| 代码评审 | 每次Merge Request | 开发人员 | CR意见+通过 |
| 测试评审 | 测试计划/用例完成后 | 测试+开发+产品 | 评审意见+签字 |
| 上线评审 | 上线前 | 全体核心成员 | 上线决策 |

### 4.2 评审检查清单

每份文档发布前须通过以下检查：

- [ ] 文档编号和名称正确
- [ ] 版本号和日期已更新
- [ ] 文档负责人和审批人已指定
- [ ] 内容完整，无TODO或占位符
- [ ] 格式符合模板规范
- [ ] 引用文档的编号和版本正确
- [ ] 已通过同行评审
- [ ] 修订记录已更新
