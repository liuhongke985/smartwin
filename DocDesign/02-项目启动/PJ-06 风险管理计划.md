## 1. 风险管理概述

### 1.1 风险管理目标

识别、评估和应对项目全生命周期中的各类风险，将风险对项目目标的影响降到最低，确保项目按期、按质、按预算交付。

### 1.2 风险管理流程

```
风险识别 → 风险评估 → 风险应对 → 风险监控 → 风险关闭
   ↑                                    │
   └──────────── 反馈 ─────────────────┘
```

### 1.3 风险评估矩阵

**概率等级**：

| 等级 | 概率 | 说明 |
|:----:|:----:|------|
| 高 | >70% | 很可能发生 |
| 中 | 30%-70% | 可能发生 |
| 低 | <30% | 不太可能发生 |

**影响等级**：

| 等级 | 影响 | 说明 |
|:----:|------|------|
| 高 | 严重影响 | 延期>1月或超支>20%或功能缺失 |
| 中 | 中等影响 | 延期2周-1月或超支10%-20% |
| 低 | 轻微影响 | 延期<2周或超支<10% |

**风险等级矩阵**：

| | 低概率 | 中概率 | 高概率 |
|---|:---:|:---:|:---:|
| **高影响** | 中 | 高 | 极高 |
| **中影响** | 低 | 中 | 高 |
| **低影响** | 极低 | 低 | 中 |

## 3. 风险应对策略

### 3.1 应对策略类型

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **规避** | 改变计划消除风险 | 高风险、不可接受 |
| **转移** | 将风险转给第三方 | 外包、保险 |
| **减轻** | 降低概率或影响 | 技术风险 |
| **接受** | 不采取行动，做好应急 | 低风险 |
| ** exploiting** | 确保机会实现 | 正面风险 |

### 3.2 Top 5 风险应对方案

#### R-01 达梦DM8适配难度

| 项 | 内容 |
|----|------|
| 策略 | 减轻 |
| 行动1 | M1 W1-2 立即启动达梦DM8适配验证POC |
| 行动2 | 建立MySQL降级方案，双数据库适配 |
| 行动3 | 与达梦技术支持建立联系通道 |
| 触发条件 | M2底DM8适配未通过70% |
| 应急方案 | 切换MySQL方案，M3恢复DM8 |

#### R-06 团队招聘不及时

| 项 | 内容 |
|----|------|
| 策略 | 减轻+转移 |
| 行动1 | 项目批准后立即启动全员招聘 |
| 行动2 | 与外包公司签订备用协议 |
| 行动3 | 允许远程办公，扩大招聘范围 |
| 触发条件 | M1底到岗<60% |
| 应急方案 | 启动外包，关键岗位由架构师兼任 |

#### R-02 AI检测准确率不达标

| 项 | 内容 |
|----|------|
| 策略 | 减轻 |
| 行动1 | 规则引擎+AI模型双引擎检测 |
| 行动2 | 建立标注数据集持续训练 |
| 行动3 | 设置准确率阈值，低于85%不发布 |
| 触发条件 | M6底检测准确率<80% |
| 应急方案 | 延长AI引擎开发Sprint，规则引擎先上 |

#### R-09 关键人员离职

| 项 | 内容 |
|----|------|
| 策略 | 减轻 |
| 行动1 | 核心岗位AB角备份 |
| 行动2 | 强制文档化，代码注释规范 |
| 行动3 | 团队建设、薪酬激励 |
| 触发条件 | 核心成员提出离职 |
| 应急方案 | AB角接手，紧急招聘 |

#### R-10 进度延期连锁

| 项 | 内容 |
|----|------|
| 策略 | 减轻 |
| 行动1 | 关键路径每周跟踪 |
| 行动2 | 每阶段预留1周缓冲期 |
| 行动3 | 非核心功能可降级到V1.1 |
| 触发条件 | 里程碑偏差>2周 |
| 应急方案 | 范围裁剪，非P0功能延后 |

## 4. 风险监控机制

### 4.1 风险评审节奏

| 活动 | 频率 | 参与人 | 产出 |
|------|:----:|--------|------|
| 风险扫描 | 每Sprint | 全员 | 新风险识别 |
| 风险评审 | 每周 | 项目经理+组长 | 风险登记册更新 |
| 风险升级 | 按需 | 项目总监 | 升级决策 |
| 风险报告 | 每月 | 项目经理 | 月报风险章节 |

### 4.2 风险状态定义

| 状态 | 说明 |
|------|------|
| 🟢 已关闭 | 风险已消除或已应对 |
| 🟡 监控中 | 风险存在但可控，持续监控 |
| 🔴 升级中 | 风险超出项目组控制，需升级 |
| ⚪ 新识别 | 刚识别，待评估 |
