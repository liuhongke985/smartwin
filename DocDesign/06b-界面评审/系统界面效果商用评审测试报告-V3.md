## 一、评审总览

### 1.1 V2→V3 评审变化说明

V2.4报告主要聚焦于**功能新增**（版本Diff、模板库、保存过滤器、微交互动画等），评分达到8.8/10。  
V3评审在此基础上，以**商用标准**重新审视全部页面的**数据真实性、流程完整性、错误处理、加载体验**，发现V2.4报告中未覆盖的深层问题：

- **9个页面使用硬编码mock数据**（无API调用，数据不会随实际业务变化）
- **3个页面图表使用 `Math.random()`** 生成假数据
- **12+个页面使用 `console.error` 替代用户可见的Toast错误提示**
- **15+个页面无加载骨架屏/Loading状态**
- **7+个页面API失败后降级到本地硬编码mock数据**
- **2个核心功能弹窗为空壳**（创建预算、偏好设置保存）
- **1个数据映射Bug**（RiskDashboard summary对象被API返回值覆盖）

### 1.3 评审方法论

本次评审采用以下方法：
1. **逐文件源码审阅** — 对59个页面Vue文件逐一阅读 `<script setup>` 和 `<template>` 部分
2. **数据流追踪** — 检查每个页面的 `onMounted` → `API调用` → `数据绑定` → `渲染` 链路完整性
3. **硬编码检测** — 检查 `ref([...])` 初始化是否为mock数据、`Math.random()` 使用、硬编码数字
4. **错误处理审查** — 检查 `catch` 块是否使用 `toast.error()` 而非 `console.error()`
5. **加载状态审查** — 检查是否有 `loading` ref + Skeleton/Spinner 组件
6. **业务流程验证** — 检查创建/编辑/删除操作是否调用真实API

### 3.13 [V3-P1-04] RiskDashboardView summary赋值Bug

**文件:** `views/dashboard/RiskDashboardView.vue`  
**问题:**
```typescript
const summary = ref({ total: 0, high: 0, medium: 0, low: 0, pending: 0 })

onMounted(async () => {
  try {
    summary.value = await riskApi.summary()  // ← Bug！
    // API 返回 { byStatus, bySeverity, byType, total, todayNew, generatedAt }
    // 直接赋值会覆盖 summary 结构，导致 summary.high / summary.medium 等全部变为 undefined
    // 应该像 RiskOverviewView 那样做字段映射
```
- `summary.value = await riskApi.summary()` 直接覆盖对象
- 导致统计卡显示 undefined

**修复方案:**
- 参照 RiskOverviewView 的正确做法进行字段映射：
```typescript
const raw = await riskApi.summary() as any
const bySeverity = raw.bySeverity || {}
const byStatus = raw.byStatus || {}
summary.value = {
  total: raw.total || 0,
  high: (bySeverity.high || 0) + (bySeverity.critical || 0),
  medium: bySeverity.medium || 0,
  low: bySeverity.low || 0,
  pending: byStatus.pending || 0,
}
```

### 6.1 商用就绪度评估

SmartWin智链平台（smartchain-frontend）经V3商用标准评审后，**商用就绪度从91%下降至82%**：

- 权限体系支持功能权限+数据权限+路由守卫+菜单过滤

- 交互体验达标（无原生alert/prompt/confirm + 微交互动画）

**阻断商用的部分：**
- **9个页面数据完全造假**（硬编码mock或Math.random），商用环境下展示假数据
- **2个功能弹窗为空壳**（创建预算/偏好设置），用户操作后无实际效果
- **注册流程不完整**（setTimeout模拟，用户无法真正注册）
- **12+页面错误处理不到位**（console.error而非toast），用户无法感知失败

### 6.2 主要风险

1. **数据真实性风险**（9页P0）— 商用环境中展示假数据，误导决策
2. **功能完整性风险**（2页P0+3页P1）— 核心功能弹窗为空壳或无API
3. **用户体验风险**（15+页无loading+12+页console.error）— 商用体验不达标
4. **数据降级风险**（7+页降级mock）— API失败展示假数据，合规风险

### 6.3 建议

   - 移除所有硬编码mock数据
   - 移除所有 `Math.random()` 
   - 所有页面 `onMounted` 必须调用真实API
   - 所有创建/编辑/删除操作必须调用API

   - 所有catch块使用 `toast.error()` 而非 `console.error()`
   - 所有列表/图表页面添加loading骨架屏
   - API失败显示错误状态 + 重试（不降级到mock）

5. **修复完成后** 重新进行V4评审，目标商用就绪度 ≥ 95%

### 8.2 [V3.1-02] 风险处置流程增强（RiskHandleView 完全重写 ✅）

**问题:**
- 处置历史为硬编码mock数据（非API获取）
- 事件加载效率极低（加载100条事件再前端过滤1条）
- 无错误状态/重试机制
- 无步骤验证（可跳过必填步骤）
- 无权限控制（任何人可提交处置）
- 空catch块无用户提示

**修复内容:**

| 优化项 | 修复前 | 修复后 |
|--------|--------|--------|
| 事件加载 | `riskApi.events({page:1,size:100})` 后前端find | `riskApi.eventDetail(id)` 直接获取单条 |
| 处置历史 | 硬编码mock数据 | `riskApi.eventHistory(id)` 从API获取 |
| 错误处理 | 空catch块 | toast.error + 错误状态页 + 重试按钮 |
| 步骤验证 | 无验证，可跳过 | Step2验证(影响范围+紧急程度必填) + Step3验证(处置方式必选) |
| AI建议 | 无 | 基于严重等级+紧急程度智能推荐处置方式 |
| 权限控制 | 无 | `v-permission="'risk:handle'"` 按钮级权限 + `can('risk:handle')` 提交前校验 |
| 数据提交 | 仅action+remark | 完整提交(impactScope/urgency/rootCause/impactAssessment) |
| 加载状态 | 简单spinner | 骨架屏(skeleton-header/steps/content) |
| 未找到状态 | 无 | 独立"未找到该风险事件"页面+返回按钮 |

**新增API方法:**
- `riskApi.eventDetail(id)` — 获取单条风险事件详情
- `riskApi.eventHistory(id)` — 获取风险事件处置历史
- `riskApi.handleEvent()` 扩展参数 — 支持 impactScope/urgency/rootCause/impactAssessment

**新增类型:**
- `RiskHistoryItem` — 风险处置历史记录类型
