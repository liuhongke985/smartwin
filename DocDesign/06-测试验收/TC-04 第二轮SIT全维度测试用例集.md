## 2. M01 认证授权模块

### 2.1 功能测试增强 (FT2-M01)

#### SIT2-FT-M01-001: 端到端登录-权限-操作-审计全链路
- **优先级**: P0
- **测试类型**: 功能测试(端到端链路)
- **前置条件**: 用户 `admin@smartwin.com` 已注册，角色为系统管理员
- **测试链路**: 登录 → 获取Token → 加载菜单 → 访问用户管理 → 操作用户 → 审计日志记录
- **测试步骤**:
  1. POST `/api/auth/login` body: `{"username":"admin@smartwin.com","password":"SmartWin@2028"}`
  2. 提取返回的 `accessToken` 和 `refreshToken`
  3. GET `/api/system/menus` Header: `Authorization: Bearer {accessToken}`
  4. 验证返回菜单树包含"系统管理 > 用户管理"
  5. GET `/api/system/users?page=1&size=10` Header: `Authorization: Bearer {accessToken}`
  6. 验证返回用户列表，HTTP 200
  7. POST `/api/system/users` body: `{"username":"test_user_001","email":"test001@smartwin.com","phone":"13800138001","roleId":2}` 创建用户
  8. GET `/api/audit/logs?module=USER&action=CREATE&startTime={5分钟前}` 查询审计日志
- **预期结果**:
  - 步骤1: HTTP 200, 返回 `accessToken`(JWT格式, 含userId/roles/exp), `refreshToken`
  - 步骤3: HTTP 200, 菜单树结构正确, 包含用户管理菜单项
  - 步骤5: HTTP 200, 返回分页用户列表, `data.records` 数组非空
  - 步骤7: HTTP 200, 返回新用户ID, 用户状态为ACTIVE
  - 步骤8: 审计日志包含一条 `module=USER, action=CREATE, operator=admin@smartwin.com, target=test_user_001` 的记录
- **验证方法**: API验证 + 数据库验证(audit_log表) + 日志验证

#### SIT2-FT-M01-002: Token过期→刷新→恢复操作全链路
- **优先级**: P0
- **测试链路**: 登录获取Token → 等待Token过期 → 请求被拒 → 刷新Token → 恢复操作
- **测试步骤**:
  1. 登录获取 `accessToken`(TTL=30min) 和 `refreshToken`(TTL=7d)
  2. 手动修改Redis中Token的TTL为1秒，等待2秒
  3. GET `/api/system/users` 使用过期Token
  4. POST `/api/auth/refresh` body: `{"refreshToken":"{refreshToken}"}`
  5. 使用新Token再次 GET `/api/system/users`
- **预期结果**:
  - 步骤3: HTTP 401, `{"code":401,"message":"Token已过期"}`
  - 步骤4: HTTP 200, 返回新的 `accessToken`
  - 步骤5: HTTP 200, 正常返回用户列表

#### SIT2-FT-M01-003: 修改密码→旧Token失效→重新登录全链路
- **优先级**: P0
- **测试链路**: 登录 → 修改密码 → 旧Token失效验证 → 重新登录 → 新Token可用
- **测试步骤**:
  1. 登录获取Token-A
  2. 使用Token-A POST `/api/auth/change-password` body: `{"oldPassword":"SmartWin@2028","newPassword":"SmartWin@2029"}`
  3. 使用Token-A GET `/api/system/users` (验证旧Token已失效)
  4. 使用旧密码登录(验证失败)
  5. 使用新密码登录获取Token-B
  6. 使用Token-B GET `/api/system/users`
- **预期结果**:
  - 步骤2: HTTP 200, 密码修改成功
  - 步骤3: HTTP 401, Token已加入Redis黑名单
  - 步骤4: HTTP 401, 密码错误
  - 步骤5: HTTP 200, 返回新Token-B
  - 步骤6: HTTP 200, 正常访问
- **验证方法**: API验证 + Redis验证(黑名单key存在)

#### SIT2-FT-M01-004: 并发登录→多端Token独立性
- **优先级**: P1
- **测试步骤**:
  1. 从3个不同User-Agent(PC/移动端/平板)同时登录同一用户
  2. 验证3个Token均有效且独立
  3. 在PC端登出
  4. 验证移动端和平板端Token仍然有效
- **预期结果**:
  - 3个Token互不影响, 单端登出不影响其他端

#### SIT2-FT-M01-005: 登录失败锁定→自动解锁全链路
- **优先级**: P0
- **测试链路**: 连续失败5次 → 账户锁定 → 等待15分钟 → 自动解锁 → 登录成功
- **测试步骤**:
  1. 连续5次使用错误密码登录 `admin@smartwin.com`
  2. 第6次使用正确密码登录(验证仍被锁定)
  3. 手动修改Redis锁定key的TTL为1秒，等待2秒
  4. 使用正确密码登录
- **预期结果**:
  - 步骤1: 第5次失败后返回 `{"code":423,"message":"账户已锁定，请15分钟后重试"}`
  - 步骤2: HTTP 423, 仍被锁定
  - 步骤4: HTTP 200, 登录成功
