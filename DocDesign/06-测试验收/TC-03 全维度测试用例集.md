## 2. M01 认证授权模块

### 2.1 功能测试 (FT-M01)

#### FT-M01-001: 用户登录-正确凭据
- **优先级**: P0
- **前置条件**: 用户已注册且状态正常
- **测试步骤**:
  1. 访问登录页 `/login`
  2. 输入正确用户名 `admin@smartwin.com`
  3. 输入正确密码 `SmartWin@2028`
  4. 点击「登录」按钮
- **预期结果**:
  - HTTP 200，返回 JWT Token
  - 前端跳转至 `/dashboard`
  - 用户信息存入 Pinia Store
  - 审计日志记录登录成功

#### FT-M01-002: 用户登录-错误密码
- **优先级**: P0
- **前置条件**: 用户已注册
- **测试步骤**:
  1. 访问登录页
  2. 输入正确用户名
  3. 输入错误密码 `wrongpassword`
  4. 点击「登录」
- **预期结果**:
  - HTTP 401，返回错误提示「用户名或密码错误」
  - 前端不跳转，显示 Toast 错误
  - 审计日志记录登录失败

#### FT-M01-003: 用户登录-连续5次失败后锁定
- **优先级**: P0
- **前置条件**: 用户已注册
- **测试步骤**:
  1. 连续输入错误密码 5 次
  2. 第 6 次尝试登录
- **预期结果**:
  - 前5次返回 401 + 错误计数
  - 第6次返回 423 + 「账户已锁定，请15分钟后重试」
  - Redis 记录锁定状态及过期时间

#### FT-M01-004: 用户登录-回车提交
- **优先级**: P1
- **前置条件**: 登录页已加载
- **测试步骤**:
  1. 在密码输入框中输入凭据
  2. 按下键盘 Enter 键
- **预期结果**:
  - 触发登录提交，与点击按钮行为一致
  - 不需要手动点击登录按钮

#### FT-M01-005: 获取当前用户信息
- **优先级**: P0
- **前置条件**: 用户已登录，Token 有效
- **测试步骤**:
  1. 携带 Token 调用 `GET /api/auth/me`
- **预期结果**:
  - HTTP 200，返回用户信息（id/username/roles/permissions/avatar）
  - 不返回敏感字段（password/salt）

#### FT-M01-006: Token 过期自动刷新
- **优先级**: P1
- **前置条件**: Token 即将过期（剩余 < 5分钟）
- **测试步骤**:
  1. 使用即将过期的 Token 发起请求
  2. 网关拦截并检查 Token 过期时间
  3. 使用 RefreshToken 获取新 Token
- **预期结果**:
  - 原请求正常完成
  - 响应头返回新 Token
  - 用户无感知

#### FT-M01-007: Token 过期后请求拒绝
- **优先级**: P0
- **前置条件**: Token 已过期（超过30分钟未刷新）
- **测试步骤**:
  1. 使用过期 Token 调用 API
- **预期结果**:
  - HTTP 401
  - 前端拦截 401，清除 Token，跳转登录页
  - 提示「登录已过期，请重新登录」

#### FT-M01-008: 用户登出
- **优先级**: P0
- **前置条件**: 用户已登录
- **测试步骤**:
  1. 点击用户头像下拉菜单中的「退出登录」
  2. 确认退出
- **预期结果**:
  - 前端清除 Token/用户信息
  - 后端将 Token 加入黑名单
  - 跳转至登录页
  - 审计日志记录登出

#### FT-M01-009: 多端登录并行
- **优先级**: P1
- **前置条件**: 同一账号在两台设备可用
- **测试步骤**:
  1. 设备A登录
  2. 设备B使用同一账号登录
  3. 设备A发起 API 请求
- **预期结果**:
  - 两端均可正常访问
  - 设备A的 Token 仍然有效
  - 不互斥（允许多端在线）

#### FT-M01-010: 修改密码后旧Token失效
- **优先级**: P0
- **前置条件**: 用户已登录
- **测试步骤**:
  1. 进入安全设置页 `/profile/security`
  2. 输入旧密码、新密码、确认新密码
  3. 提交修改
  4. 使用旧 Token 发起 API 请求
- **预期结果**:
  - 密码修改成功
  - 前端自动调用 `authStore.logout()` 清除 Token
  - 延迟2秒后跳转登录页
  - 旧 Token 请求返回 401

#### FT-M01-011: 验证码-登录失败触发
- **优先级**: P1
- **前置条件**: 登录失败次数 ≥ 3
- **测试步骤**:
  1. 输入用户名密码
  2. 页面显示图形验证码
  3. 输入错误验证码
  4. 点击登录
- **预期结果**:
  - 验证码不匹配，返回 400
  - 提示「验证码错误」
  - 刷新验证码

#### FT-M01-012: 开发环境默认凭据显示
- **优先级**: P1
- **前置条件**: 处于开发环境 (`import.meta.env.DEV === true`)
- **测试步骤**:
  1. 访问登录页
  2. 检查页面是否显示默认凭据提示
- **预期结果**:
  - DEV 环境显示默认凭据提示框
  - 生产环境 (`PROD`) 不显示

#### FT-M01-013: 密码强度校验
- **优先级**: P0
- **前置条件**: 无
- **测试步骤**:
  1. 尝试使用弱密码注册/修改密码（如 `123456`、`abc`）
  2. 尝试使用强密码（12位+大小写+数字+特殊字符）
- **预期结果**:
  - 弱密码被拒绝，提示密码复杂度要求
  - 强密码通过校验

#### FT-M01-014: 角色权限动态菜单
- **优先级**: P1
- **前置条件**: 不同角色用户已配置不同菜单权限
- **测试步骤**:
  1. 管理员角色登录，查看菜单
  2. 普通用户角色登录，查看菜单
- **预期结果**:
  - 管理员看到全部菜单
  - 普通用户仅看到授权菜单
  - 未授权页面路由直接跳转 403

#### FT-M01-015: 登录页加载性能
- **优先级**: P2
- **前置条件**: 网络正常
- **测试步骤**:
  1. 清空浏览器缓存
  2. 访问登录页
  3. 记录 FCP/LCP/TTI
- **预期结果**:
  - FCP < 1.8s
  - LCP < 2.5s
  - TTI < 3.5s
