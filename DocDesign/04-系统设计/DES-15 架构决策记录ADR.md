## 一、ADR概述

### 1.1 目的

架构决策记录（Architecture Decision Record, ADR）是捕获架构决策的轻量级文档，记录每个重要技术决策的背景、方案、选择原因和影响。

### 1.2 ADR模板

每条ADR包含以下结构：
- **编号**: ADR-XXX
- **标题**: 决策标题
- **状态**: 提议/接受/废弃/替代
- **日期**: 决策日期
- **背景**: 为什么需要做这个决策
- **方案**: 候选方案及分析
- **决策**: 最终选择
- **影响**: 该决策带来的影响

## 二、架构决策记录

### ADR-001: 微服务架构选型

| 项目 | 内容 |
|------|------|
| **状态** | ✅ 接受 |
| **日期** | 2026-07-01 |
| **背景** | 平台需要支持独立可售+无缝集成两种模式，各模块需独立部署和扩展 |
| **候选方案** | ① 单体架构 ② 微服务架构 ③ SOA架构 |
| **决策** | 选择②微服务架构，基于Spring Boot + Spring Cloud |
| **理由** | 微服务支持独立部署、独立扩展、技术栈灵活，符合多模式架构需求 |
| **影响** | 增加服务治理复杂度，需引入服务注册发现、配置中心、API网关 |

### ADR-002: 数据库选型

| 项目 | 内容 |
|------|------|
| **状态** | ✅ 接受 |
| **日期** | 2026-07-01 |
| **背景** | 需要同时支持开源数据库和国产信创数据库 |
| **候选方案** | ① MySQL ② PostgreSQL ③ 达梦DM8 ④ 双数据库适配 |
| **决策** | 以PostgreSQL为主开发数据库，通过方言适配层同时支持达梦DM8 |
| **理由** | PostgreSQL功能强大且开源，达梦DM8是信创首选，方言适配层实现低成本兼容 |
| **影响** | 需开发common-db-multi多数据库适配模块，SQL需兼容两种数据库 |

### ADR-010: 国密安全策略（V2.0）

| 项目 | 内容 |
|------|------|
| **状态** | ✅ 接受 |
| **日期** | 2026-07-01 |
| **背景** | 量子计算威胁传统密码学，需提前布局后量子密码 |
| **候选方案** | ① 纯PQC替换 ② 纯QKD ③ 混合加密（PQC+传统+QKD） |
| **决策** | 选择③混合加密方案，过渡期使用PQC+传统算法，QKD用于高安全场景 |
| **理由** | PQC尚未完全标准化，纯替换风险高；混合方案兼顾安全性和兼容性 |
| **影响** | 新增QuantumSecurityService，密钥管理复杂度增加 |
