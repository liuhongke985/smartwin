## 1. 概述

### 1.1 目的

本文档定义SmartWin平台的配置管理策略，确保开发、测试、生产环境的配置一致性、可追溯性和安全性。

### 1.2 适用范围

适用于SmartWin平台全部子系统（智链、智数、智赢平台、运营推广平台）的配置管理。

---

## 2. 配置管理架构

### 2.1 配置层次

| 层次 | 管理工具 | 说明 |
|------|----------|------|
| 代码级配置 | Git + Spring Profiles | application.yml / application-{profile}.yml |
| 集中配置 | Nacos Config Server | 动态配置、灰度发布 |
| 环境变量 | Docker ENV / K8s ConfigMap | 容器化部署配置 |
| 敏感配置 | K8s Secret / Vault | 密码、密钥、证书 |

### 2.2 Spring Profile 体系

| Profile | 用途 | 对应文件 |
|---------|------|----------|
| `dev` | 开发环境 | application-dev.yml |
| `test` | 测试环境 | application-test.yml |
| `prod` | 生产环境 | application-prod.yml |
| `saas` | SaaS多租户模式 | application-saas.yml |
| `integrated` | 集成模式(智链+智数) | application-integrated.yml |
| `sd` | 智数独立模式 | application-sd.yml |
| `sc` | 智链独立模式 | application-sc.yml |
| `xinchuang` | 信创环境 | application-xinchuang.yml |

## 3. 配置项分类

### 3.1 数据源配置

```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/${DB_NAME:smartwin}
    username: ${DB_USER:root}
    password: ${DB_PASSWORD}
    driver-class-name: com.mysql.cj.jdbc.Driver
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 30000
      idle-timeout: 600000
```

### 3.2 Redis配置

```yaml
spring:
  redis:
    host: ${REDIS_HOST:localhost}
    port: ${REDIS_PORT:6379}
    password: ${REDIS_PASSWORD:}
    database: 0
    lettuce:
      pool:
        max-active: 16
        max-idle: 8
        min-idle: 2
```

### 3.3 JWT配置

```yaml
smartwin:
  security:
    jwt:
      secret: ${JWT_SECRET}
      expiration: 86400000  # 24h
      refresh-expiration: 604800000  # 7d
```

### 3.4 多租户配置

```yaml
smartwin:
  tenant:
    mode: ${TENANT_MODE:saas}  # saas | private | product
    default-tenant: default
```

## 4. 配置变更流程

### 4.1 变更审批

| 变更类型 | 审批级别 | 时效要求 |
|----------|----------|----------|
| 紧急修复(热补丁) | 技术负责人 | 2小时内 |
| 常规配置调整 | DevOps + 业务确认 | 1个工作日 |
| 架构级变更 | 架构委员会 | 3个工作日 |

### 4.2 变更步骤

1. 提交变更申请（含变更内容、影响分析、回滚方案）
2. 审批通过后，在Nacos/ConfigMap中修改配置
3. 验证配置生效（健康检查 + 功能测试）
4. 记录变更日志
5. 如异常，执行回滚

## 5. 密钥管理

| 密钥类型 | 存储位置 | 轮换周期 |
|----------|----------|----------|
| 数据库密码 | K8s Secret | 90天 |
| JWT密钥 | K8s Secret | 180天 |
| API Key | Vault | 90天 |
| TLS证书 | K8s Secret + cert-manager | 自动续期 |
| 国密密钥 | HSM/软件密钥库 | 按合规要求 |

---

## 6. 配置审计

- 所有配置变更通过Git版本控制，保留完整变更历史
- Nacos配置变更自动记录操作人、时间、变更内容
- 生产环境配置每月审计一次
- 敏感配置不进入代码仓库，通过CI/CD注入
